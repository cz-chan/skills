## 1. Qué hay que hacer ahora

Una tabla de base de datos se parece a una hoja de Excel: tiene columnas con nombre y cada fila es un dato. **En este paso solo creas la hoja vacía, con sus encabezados.**

Así queda al terminar el paso:

| id | post_id | created_at |
|---|---|---|
| *(sin filas)* | | |

Más adelante (paso 4), cada click añadirá una fila. Imagina tres clicks:

**Click en `receta-tortilla`:**

| id | post_id | created_at |
|---|---|---|
| 1 | receta-tortilla | 09:00 |

**Otro click en `receta-tortilla`:**

| id | post_id | created_at |
|---|---|---|
| 1 | receta-tortilla | 09:00 |
| 2 | receta-tortilla | 09:30 |

**Click en `viaje-roma`:**

| id | post_id | created_at |
|---|---|---|
| 1 | receta-tortilla | 09:00 |
| 2 | receta-tortilla | 09:30 |
| 3 | viaje-roma | 09:45 |

Para saber cuántos likes tiene `receta-tortilla`, se cuentan sus filas: **2**. Para `viaje-roma`: **1**. Ese número es el que mostrará el botón (paso 5).

Si recargas la página, las filas siguen ahí porque se guardan en Neon, no en el navegador.

**Para qué sirve cada columna:**
- **`post_id`** dice a qué post va el like. Sin ella, no sabrías separar los de `receta-tortilla` de los de `viaje-roma`.
- **`created_at`** dice cuándo se dio el like. La rellena la base de datos sola.
- **`id`** es el número de cada fila. También lo pone la base de datos, y sirve para distinguir dos likes aunque se parezcan.

Tu tarea son unas 5 líneas de SQL (el lenguaje para hablar con la base de datos) que crean esa hoja vacía. Te guío paso a paso cuando empecemos.
