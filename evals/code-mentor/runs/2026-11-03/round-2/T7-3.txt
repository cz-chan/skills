## Paso 1: dónde guardar la conexión

**El problema.** Neon es un servidor de Postgres que está en internet. Tu código tiene que saber dónde está y con qué contraseña entrar, y todo eso va en un solo texto, la **connection string** (cadena de conexión).

**Cómo se lee.** Este es el ejemplo de la documentación de Neon, con datos inventados:

```
postgresql://alex:****@ep-cool-darkness-a1b2c3d4-pooler.us-east-2.aws.neon.tech/dbname?sslmode=require&channel_binding=require
```

| Parte | Valor | Qué es |
|---|---|---|
| Esquema | `postgresql://` | El protocolo: "esto habla Postgres" |
| Rol | `alex` | El usuario dentro de la base de datos (no tu cuenta de Neon) |
| Contraseña | `AbC123dEf` | La contraseña de ese rol |
| Host | `ep-cool-darkness-a1b2c3d4-pooler.us-east-2.aws.neon.tech` | La dirección del servidor |
| Base de datos | `dbname` | Un servidor puede tener varias; esta es la tuya |
| Opciones | `sslmode=require&channel_binding=require` | Obligan a cifrar la conexión; no las borres |

**Dónde no ponerla.** Imagina que escribes esto en `src/index.ts`:

```ts
const url = 'postgresql://alex:****@...'
```

1. Haces commit y lo subes a GitHub.
2. Cualquiera con acceso al repo lee `AbC123dEf`.
3. Con eso puede entrar en tu base de datos, leerla y borrarla.
4. Borrar la línea después no lo arregla, porque git guarda el historial. Tendrías que cambiar la contraseña.

**La solución: una variable de entorno.** El valor vive en un archivo aparte, `.env`, que git ignora. El código solo usa el nombre:

```
.env (fuera de git)            src/index.ts (en git)
DATABASE_URL=postgresql://...  ◀── lee DATABASE_URL por su nombre
```

Así el código puede ser público sin que lo sea la contraseña. Y cuando tengas Neon, solo cambias el valor en `.env`, no el código.

**El formato de `.env`** es una variable por línea, `NOMBRE=valor`, sin espacios alrededor del `=`. Por ejemplo, con otra variable:

```
API_KEY=abc123
```

## Qué tienes que hacer

Hazlo en este orden, para que `.env` ya esté ignorado cuando exista:

1. En `.gitignore`, añade una línea nueva con `.env`.
2. En la raíz del proyecto, crea `.env` con una variable llamada `DATABASE_URL`. Como valor, usa la URL de ejemplo de arriba. Cuando tengas Neon, la cambias por la real.

Cuando termines, dime "listo". Compruebo con `git check-ignore .env`, que solo mira si git ignora el archivo y debería imprimir `.env`.
