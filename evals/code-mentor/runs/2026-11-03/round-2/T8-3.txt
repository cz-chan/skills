TEXT: Vas a escribir un `CREATE TABLE`, la instrucción que crea la tabla. Tiene esta forma:

```sql
CREATE TABLE nombre_tabla (
  columna1 tipo opciones,
  columna2 tipo opciones
);
```

Las columnas van separadas por comas, sin coma tras la última, y la instrucción termina en `;`.

## Las piezas

**Tipos:** he elegido uno para cada columna, para que no tengas que buscarlos.

| Columna | Tipo | Por qué |
|---|---|---|
| `id` | `bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY` | La DB genera el número sola (1, 2, 3…) y nunca se repite |
| `post_id` | `text` | Guarda textos como `receta-tortilla` |
| `created_at` | `timestamptz` | Guarda fecha y hora, con zona horaria |

**Opciones:** en `id` ya van incluidas. Para las otras dos columnas tienes estas, y puedes usar las dos en la misma columna:

- **`NOT NULL`:** la columna no puede quedar vacía. Si intentas guardar una fila sin ese dato, la DB da error.
- **`DEFAULT now()`:** si no le pasas un valor, la DB pone la hora actual.

## Qué hacen, con un ejemplo

Cuando llegue un click, la API solo enviará `post_id = 'receta-tortilla'`. Nada más.

```
Llega:   post_id = 'receta-tortilla'
La DB completa:
  id         → 1 (lo genera ella)
  created_at → ?
```

Y si un fallo enviara un like sin `post_id`:

```
Sin NOT NULL:  2 | (vacío) | 10:05   ← se guarda un like de ningún post
Con NOT NULL:  ERROR, y no se guarda nada
```
