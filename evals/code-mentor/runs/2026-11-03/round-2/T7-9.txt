## Paso 3: crear la tabla y su primera fila

**El problema.** `ping()` comprueba que hay conexión, pero en la base de datos todavía no hay dónde guardar el contador. Sin eso, los likes no pueden sobrevivir a una recarga.

**Qué es una tabla.** Es como una hoja de cálculo con reglas: las **columnas** son fijas y cada una tiene un tipo; las **filas** son los datos. Esta es la que vamos a crear:

```
likes
 id (text) | total (integer)
-----------+----------------
 home      |              0
```

### Crear una tabla

Otra vez con un ejemplo distinto, para que veas el patrón sin la solución: un inventario de una tienda.

```sql
CREATE TABLE products (
  sku   text PRIMARY KEY,
  stock integer NOT NULL DEFAULT 0
);
```

Cada columna lleva su nombre, su tipo y sus reglas:

| Pieza | Qué significa |
|---|---|
| `text` | Guarda texto |
| `integer` | Guarda un número entero |
| `PRIMARY KEY` | Identifica la fila: el valor no puede repetirse ni faltar |
| `NOT NULL` | La columna no puede quedar vacía |
| `DEFAULT 0` | Si no das un valor, usa `0` |

### Meter una fila

```sql
INSERT INTO products (sku) VALUES ('taza');
```

Solo damos `sku`, así que Postgres rellena `stock` con el `DEFAULT`. Mira qué hace la tabla con cada intento:

| Query | Resultado | La tabla queda |
|---|---|---|
| `INSERT INTO products (sku) VALUES ('taza');` | OK | `taza, 0` |
| `INSERT INTO products (sku) VALUES ('plato');` | OK | `taza, 0` y `plato, 0` |
| `INSERT INTO products (sku) VALUES ('taza');` | ❌ Error: `taza` ya existe | Sin cambios |
| `INSERT INTO products (stock) VALUES (5);` | ❌ Error: falta `sku` | Sin cambios |

Las dos últimas filas son justo lo útil: la base de datos **rechaza los datos incorrectos**, aunque tu código tenga un fallo.

Observa también que el texto en SQL va entre comillas simples (`'taza'`), y que cada sentencia acaba en `;`.

### Por qué lo diseñamos así

- **`id` como `PRIMARY KEY`:** en el paso 4 tendremos que decir qué fila actualizar, y esto garantiza que `home` solo exista una vez. Si hubiera dos filas `home`, no sabrías cuál es el total correcto.
- **`NOT NULL DEFAULT 0`:** un contador sin likes vale `0`. Si `total` pudiera estar vacío, `total + 1` también daría vacío (`NULL`), y el contador no subiría nunca.
- **La primera fila hace falta:** un `UPDATE` cambia filas que ya existen. Sin la fila `home`, actualizar no afectaría a ninguna fila y **tampoco daría error**: el like se perdería sin aviso.

### Dónde va esto

Este SQL no va en `src/db.ts`. La tabla se crea **una sola vez**, mientras que el código de la app corre cada vez que arrancas. Por eso va en un archivo aparte, que en el paso 6 pegarás en el SQL Editor de Neon. Si lo ejecutaras dos veces, daría error porque la tabla ya existe, pero no rompería nada.
