## Paso 2: conectar el código con la base de datos

**El problema.** La URL ya está en `.env`, pero ningún código la lee ni habla con Neon. Antes de crear tablas queremos una prueba mínima de que la conexión funciona.

**Por qué `SELECT 1`.** Esta query no lee ninguna tabla: pide a Postgres que devuelva un valor fijo. Si falla, el problema tiene que ser la conexión, porque en la query no hay nada más que pueda fallar. Con `AS ok` le damos el nombre `ok` a la columna del resultado:

```
SELECT 1 AS ok;

 ok
----
  1
```

**La pieza que falta: el driver.** Un driver es la librería que habla con el servidor de base de datos. Aquí es `@neondatabase/serverless`, que ya está en tu `package.json`. Se usa en dos pasos:

```ts
import { neon } from '@neondatabase/serverless'

const sql = neon(process.env.DATABASE_URL)  // prepara: aún no consulta nada
const posts = await sql`SELECT * FROM posts WHERE id = ${postId}`  // aquí va a Neon
```

- **`process.env.DATABASE_URL`** lee la variable por su nombre.
- **`` sql`...` ``** es una función que recibe la query entre comillas invertidas.
- **`await`** espera la respuesta, porque la query viaja por internet.

**Ejemplo trazado.** Esta función lee el título de un post. Usa otra tabla a propósito, para que veas el patrón sin darte la solución:

```ts
export async function getTitle() {
  const rows = await sql`SELECT title FROM posts WHERE id = 12`
  return rows[0].title
}
```

| Momento | Valor |
|---|---|
| Postgres responde | una fila, con `title` = `'My post'` |
| `rows` | `[{ title: 'My post' }]`, un array con un objeto por fila |
| `rows[0]` | `{ title: 'My post' }`, la primera fila |
| `rows[0].title` | `'My post'` |

El resultado siempre es un array de filas, aunque solo haya una. Por eso hace falta `rows[0]`.

**Si olvidas el `await`:** `rows` sería una Promise (una respuesta que aún no ha llegado), no el array. `rows[0]` daría `undefined`, y `rows[0].title` lanzaría un error.

**Dónde falla cada cosa, para cuando lo ejecutes:**

| Situación | Dónde falla |
|---|---|
| `DATABASE_URL` no está cargada | En `neon(...)`, al arrancar |
| URL con contraseña incorrecta | En el `await` de la query, porque `neon()` no contacta con el servidor |
| Todo bien | No falla, y `ping()` devuelve `1` |

**Decisión mía:** usaremos Node con `process.env`, que es lo que muestra la documentación de Neon. Node no lee `.env` por sí solo, así que habrá que arrancar con `node --env-file=.env`. Eso me toca a mí en el paso 6.
