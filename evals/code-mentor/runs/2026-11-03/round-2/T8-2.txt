**2. Creas la tabla (este paso)**

Le dices a la DB: "crea un sitio llamado `likes`, donde cada like guarde estos tres datos". Por ahora está vacío:

```
likes
┌────┬─────────┬────────────┐
│ id │ post_id │ created_at │
├────┼─────────┼────────────┤
│        (sin filas)        │

```

Ya no hay error. La misma pregunta ahora responde `0`, y con eso este paso está terminado.

**3. Llegan los clicks (paso 4)**

Cada click añade una fila. Imagina tres clicks: dos en `receta-tortilla` y uno en `viaje-lisboa`:

```
likes
┌────┬─────────────────┬────────────┐
│ id │ post_id         │ created_at │
├────┼─────────────────┼────────────┤
│  1 │ receta-tortilla │ 10:00      │  ← 1.er click
│  2 │ receta-tortilla │ 10:05      │  ← 2.º click
│  3 │ viaje-lisboa    │ 10:07      │  ← 3.er click
└────┴─────────────────┴────────────┘
```

- **`id`:** el número de la fila, para distinguirla de las demás.
- **`post_id`:** el post que recibió el like.
- **`created_at`:** cuándo se dio el like.

**4. Cuentas los likes (paso 5)**

¿Cuántos likes tiene `receta-tortilla`? Se cuentan sus filas: **2**. Y `viaje-lisboa` tiene **1**.

Como las filas quedan guardadas en la DB, al recargar la página siguen ahí y el contador no se pierde.
