## Problema 1: la URL está escrita en el código

`src/db.ts:3` tiene la cadena de conexión dentro del archivo. Ahora no hay fuga: los valores son falsos y no hay commit. Pero al poner la URL real, la contraseña entraría en git con el siguiente commit.

La causa es de diseño, y por eso cambiarla no es inmediato. `sql` se crea al cargar el archivo, y en ese momento `env(c)` aún no puede usarse:

```
Arranca la app
  └─ se ejecuta db.ts → neon(...)        ← no hay petición, no existe c

Llega GET /db-check
  └─ Hono crea c → env(c) ya funciona    ← aquí ya se puede leer la URL
```

Por tanto, la URL debe llegar a `db.ts` cuando llega la petición. Hay dos opciones:

- **a) `ping` recibe la URL como parámetro (recomendada).** Mantiene tu separación: `index.ts` lee la configuración y `db.ts` habla con la base de datos.

Recorrido de la opción (a):

```
GET /db-check

  ├─ index.ts: ping(url)
  │    ├─ db.ts: neon(url) → sql
  │    └─ db.ts: sql`...`  → [ { ok: 1 } ] → devuelve 1
```
