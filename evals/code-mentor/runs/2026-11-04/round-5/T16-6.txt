CREATE TABLE likes (

## Por qué es así

Cada línea es una columna, con la forma `nombre tipo reglas`:

- **`id`**: identifica cada like.
  - `GENERATED ALWAYS AS IDENTITY` hace que la base de datos ponga 1, 2, 3… y no te deje poner un número a mano.
  - `PRIMARY KEY` garantiza que no se repita ni esté vacío, así que no hace falta añadir `NOT NULL`.
- **`post_id`**: dice a qué post pertenece el like. Es `text` porque guarda valores como `hola-mundo`, y `NOT NULL` porque un like sin post no tiene sentido.
- **`created_at`**: dice cuándo se dio el like. Es `timestamptz` porque guarda un instante exacto, sin depender de la zona horaria del servidor. `DEFAULT now()` lo rellena solo.

## Cómo encaja con lo demás

Como `id` y `created_at` se rellenan solos, la API solo tendrá que enviar `post_id`:

```
Clic en hola-mundo → la API envía post_id = 'hola-mundo' → fila nueva: id 1, hola-mundo, hora actual
```

Para saber el total, el paso 5 contará las filas con ese `post_id`.

## Pruébala

Hazlo en el editor SQL de Neon, en tu proyecto:

**1. Crea la tabla** ejecutando el `CREATE TABLE` de arriba.

**2. Inserta una fila de prueba y léela:**

```sql
INSERT INTO likes (post_id) VALUES ('hola-mundo');
SELECT * FROM likes;
```

Debe salir una fila con `id = 1`, `post_id = hola-mundo` y `created_at` con la hora actual.

**3. Borra la fila de prueba** para que no cuente como un like real:

```sql
DELETE FROM likes WHERE post_id = 'hola-mundo';
```

El siguiente like tendrá `id = 2`, no 1. Es normal: los números no se reutilizan.
