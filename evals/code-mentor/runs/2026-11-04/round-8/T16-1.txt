TEXT: # Retomamos: botón de like con Neon

## La foto completa
Estamos construyendo un botón de like para c12z.io, y el objetivo es que aprendas bases de datos. Estará listo cuando, al hacer clic, el contador suba y siga igual tras recargar.

- ✅ **1.** Proyecto Neon y connection string
- ✅ **2.** Conexión desde la API (`SELECT 1`)
- 👉 **3. Tabla `likes` (estamos aquí)**
- ⬜ **4.** Insertar un like
- ⬜ **5.** Contar likes por post
- ⬜ **6.** Conectar botón → API → BD

En el paso 2 comprobaste que la API habla con Neon, pero `SELECT 1` no guarda nada. Ahora hace falta un sitio donde guardar los likes.

## El problema
Alguien da like al post `hola-mundo`. Hoy hay dos caminos, y ninguno sirve:

- **Insertar en la BD:** falla con `relation "likes" does not exist`, porque la tabla no existe.
- **Usar una variable en el servidor (`let likes = 3`):** funciona hasta que el servidor se reinicia, y entonces vuelve a 0.

## La idea
Una **tabla** es una estructura fija: columnas definidas de antemano y una fila por cada dato. Aquí, **cada like es una fila**:

| id | post_id | created_at |
|---|---|---|
| 1 | hola-mundo | 2026-11-04 10:00 |
| 2 | hola-mundo | 2026-11-04 10:01 |
| 3 | otro-post | 2026-11-04 10:02 |

Con esos datos:
1. Un clic en `hola-mundo` añade la fila 4.
2. Contar las filas de `hola-mundo` da 3.
3. Si el servidor se reinicia, las filas siguen en Neon y el contador sigue en 3.

Dejamos pendiente qué columnas usar. Como estás empezando con esto, decido yo:

- **`id`:** identifica cada fila de forma única. Es la **primary key** (clave primaria).
- **`post_id`:** indica a qué post pertenece el like. Es obligatoria, porque un like sin post no sirve.
- **`created_at`:** guarda cuándo ocurrió, y la base de datos la rellena sola.
- **Sin `user_id` por ahora:** el repo no tiene login, así que estaría siempre vacía. A cambio, una persona puede dar varios likes. Se puede añadir más adelante.

## Por qué así
Lo obvio sería una sola fila por post con un contador: `hola-mundo | 3`. Es más simple y rápido de leer, pero solo guarda el total y pierde cuándo ocurrió cada like. Además, no te dejaría practicar el `INSERT` y el `COUNT` de los pasos 4 y 5, que es lo que quieres aprender.

## Qué nos da
Los likes ya tendrán dónde guardarse, y los pasos 4 y 5 podrán escribir y contar datos reales.

**Comprobación del paso:** al ejecutar `SELECT * FROM likes;` debes ver 0 filas y las tres columnas, sin el error `does not exist`.

## Cómo
```
[Botón] ──clic──▶ [API /api/likes] ──query──▶ [Neon: tabla likes]
   yo                   yo                         TÚ ← paso 3
```

1. Escribes el `CREATE TABLE` con esas tres columnas (unas 5 líneas).
2. Lo ejecutas en el SQL Editor de Neon, así que este paso no necesita código en la app.
3. Haces la comprobación de arriba.
