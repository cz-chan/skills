## Qué hay ahora
La base de datos está vacía: no hay ningún sitio donde guardar un like.

```
Click en "receta-pan"
   ──▶ la API intenta guardarlo
   ──▶ Postgres: "relation "likes" does not exist" (la tabla "likes" no existe)
   ──▶ el like se pierde
```

## Qué hacemos en este paso
Creamos la tabla `likes`. Crear una tabla no guarda ningún like: solo define qué datos tendrá cada uno. Al principio está vacía:

```
id | post_id | created_at
---+---------+-----------
(sin filas)
```

## Qué pasará después, con la tabla creada
**Click 1, en `receta-pan`, a las 18:00.** Se añade una fila:

```
id | post_id    | created_at
---+------------+-----------
1  | receta-pan | 18:00
```

**Click 2, también en `receta-pan`, a las 18:02.** Se añade otra fila, y la primera no cambia:

```
id | post_id    | created_at
---+------------+-----------
1  | receta-pan | 18:00
2  | receta-pan | 18:02
```

**Click 3, en otro post, `viaje-roma`, a las 18:05.**

```
id | post_id    | created_at
---+------------+-----------
1  | receta-pan | 18:00
2  | receta-pan | 18:02
3  | viaje-roma | 18:05
```

**¿Cuántos likes tiene `receta-pan`?** Se cuentan sus filas: **2**.

**¿Y si recargas la página?** Las filas siguen guardadas en Neon. Se vuelven a contar y sale **2** otra vez. Eso es lo que queremos conseguir: que el número no se pierda.

## Para qué sirve cada columna
Cada columna responde a una pregunta sobre el like:

| Columna | Pregunta | Ejemplo | Quién la rellena |
|---|---|---|---|
| `id` | ¿Qué fila es? | `2` | Postgres |
| `post_id` | ¿De qué post es? | `receta-pan` | La API |
| `created_at` | ¿Cuándo se dio? | `18:02` | Postgres |

No guardamos quién dio el like porque este repo no tiene login. Por eso, una misma persona podrá dar varios likes.

## Por qué no guardar solo el número
La otra opción sería guardar el total:

```
post_id    | likes
-----------+------
receta-pan | 2
```

También funciona, pero aquí ya no sabes cuándo llegó cada like. Además, tu objetivo es aprender a insertar y contar filas, y así no lo practicarías.
